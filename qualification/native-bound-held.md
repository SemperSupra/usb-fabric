# Native identity-bound HELD journal (not live recovery)

Refs #7/#18. The previous recovery proof primitive authenticates a fresh neutral-state observation, but needs the old scope, launch identity and exact held record. This source increment introduces a separate fail-closed native v3 record format in the ORIGINAL journal, atomically carrying old lease scope and launch digest with HELD. Existing v1/v2 paths reject it; there is no clear or grant API. Legacy HELD or v2 never converts. The original bounded no-follow byte reader and atomic fsync+rename+parent-fsync writer are shared; nested duplicate/unknown keys fail closed. Recovery binding hashes actual bytes read on the same descriptor, not JSON reserialization.

The retained host owner must supply independently observed, protected launch/device/guest identity and pinned key, hold a stable private journal directory and serialize operations. This primitive does not verify QEMU process incarnation itself, observe guest evdev state, or authorize a lease. No runtime callers changed: wiring before real input, trusted persistent launch pin, independent neutral sensor, actual QMP ACK, rechecks under the retained owner, durable release design and live crash qualification remain open. Legacy unbound HELD remains quarantined. Source qualification status belongs in issue/PR receipt.
