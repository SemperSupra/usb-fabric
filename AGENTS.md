# Agent operating contract

GitHub is the durable, legible, executable system of record. Humans, automation, and autonomous reasoning agents use the same issue-linked worksets, source, evidence and release criteria. Read this file, repository metadata, CURRENT_TASK.md, relevant issue comments, exact refs and active claims before changes.

Claim bounded, nonoverlapping scope in an issue; record actor/harness/version, model/effort if applicable, UTC session, repo/branch/head and runtime. Work in an issue-linked branch and separate clean worktree. No direct agent pushes to main after the initial empty-repository seed; review via draft PR. Never force-push, overwrite others' work or delete active refs. Preserve original provenance, RED results, and any local work before reconciliation. Source authority transfers only after explicit accepted migration; do not invent competing queues or duplicate runtime authorities.

Use standard public free-tier execution only for explicitly public-safe source and admitted jobs; no paid private CI, secrets, private source, production, physical hardware, or unapproved release. Validate exact source with appropriate positive/negative independent oracles. Report actual commands, OS/toolchain, wall/CPU/RSS/disk and tokens/context where available; UNKNOWN otherwise. Distinguish fixture/source/runtime/HIL proof. No verdict promotion based on tool success alone. Review source classification and workflow routing before every new CI route; no broad inherited triggers. Retain bounded artifact digests/expiry and cleanup evidence.

Before handoff reconcile Git + issue/PR + current baton. Review security, release and governance changes with owner; a draft is not release approval. Use only approved public references in this public repository.
